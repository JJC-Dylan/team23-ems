[Heading 1] 2 Background&Business Context
MeítǐShāngchéng is a new hardware store funded by its parent company Jupiter,preparing to open its first physical shop in Zhengzhou.Existing Jupiter-managed stores rely on Excel spreadsheets and online calendars for employee record-keeping and shift arrangement.
These existing tools are cumbersome,unreliable and fragmented.There is no centralized system to store employee data(name,address,hourly wage)or manage daily work shifts.HR staff and supervisors struggle to add or remove staff,view workforce statistics,search employee records or assign shifts without error-prone manual work.
Client priority:Employee management is the highest-priority objective for this project iteration.Product-stock management will only be considered if the team has remaining spare time.All other advanced features belong to future product versions.Three fixed daily shifts:Morning,Afternoon,Evening.
[Heading 2] 2.1 Scope and Objectives
Employee management module(Must-have,core for current release)Complete employee record management,employee query,manual shift assignment,shift viewing,with role permission separation for HR,Supervisor and Ordinary Employee.
Inventory/stock-management module(Conditional Could-have)Only implemented if employee-management functions are fully finished and extra development time remains.Not mandatory deliverable.
Advanced functions(Won’t-have for current iteration)Department management,in-store attendance registration,depot restock request handling,management statistics dashboard,employee self-service website are postponed to future versions.

[Heading 1] 4 Assumptions and Constraints
[Heading 2] 4.1 Constraints
Time constraint:Waterfall phase runs from Week 4 to Week 9.All deliverables must be completed before Week 9,including mid-term presentation and final go/no-go evaluation.
Methodology constraint:Follow Waterfall model first,then iterative refinement.
Version-control constraint:All team members contribute via shared GIT repository from individual devices.
Functional constraint:Only manual shift assignment supported;automatic shift generation is excluded.
Deployment constraint:Deliver desktop-only application.Employee web portal will not be delivered.
Performance constraint:Support maximum 10 concurrent logged-in users.
Scope constraint:Employee management is highest priority;inventory management is optional secondary feature.

Login accounts for HR,Supervisor and Ordinary Employee are created outside this application.
Three fixed shift types(Morning/Afternoon/Evening);custom shift creation is not required.
This software is an internal shop-administration tool;it will not be exposed to public internet.

[Heading 1] 6 Application GUI Views
Login View:Login screen for username-password input.After login,menu options and button visibility change according to the logged-in user role.
Employee Overview View:Table view listing all employees;includes a search box.HR sees the Add/Edit/Delete action buttons.For Supervisor these modification buttons are hidden.Ordinary Employee cannot access this page.
Employee Detail and Edit View:Displays employee personal data.HR can edit the fields and open the shift-assignment panel.For Supervisor the input boxes are disabled,showing read-only data.Ordinary Employee cannot access this page.
Shift Assignment Panel View:Drop-down selector for Morning/Afternoon/Evening shift plus a confirm-save button.This panel is visible only for the Supervisor actor;HR performs personnel-file operations,not daily shift assignment.
Full-Store Shift Overview View:Table showing every employee and their assigned work shift.Accessible to HR and Supervisor;shift-modification controls are hidden for Supervisor.Ordinary Employee reaches their own schedule through the separate"My Work Shifts"view.

[Heading 2] Use Case 1:HR adds new employee(FR01)
<<<TABLE 8: 7r x 2c>>>
Item | Content
Use Case title | HR adds new employee
Actor | Human Resources(HR)
Precondition | HR is logged into the system and holds employee-record management permission.
Trigger | HR clicks the"Add new employee"button on the employee overview page.
Main Success Scenario | 1.System opens the new-employee input form. 2.HR fills in the employee name,address and hourly wage. 3.HR submits the form. 4.System validates the input field contents. 5.System saves the new employee record to the database. 6.System refreshes the employee overview list;the new employee entry is displayed.
Extensions | 1A(Step 4):A mandatory field is left empty or the hourly wage contains an invalid value. 1.System displays a user-friendly error message. 2.The system stays on the input form,preserves the data already entered,and terminates the use case.

[Heading 1] 9 System Overall Overview
This desktop-oriented employee-management system is built for MeítǐShāngchéng hardware store in Zhengzhou.It solves the pain point of fragmented,Excel-based manual personnel and shift management.
Three distinct end-user roles are defined,with strict role-based access control.(1)HR takes charge of the employee-record lifecycle:add,edit and delete employee personal records,and cross-check all employee and shift data;HR is not responsible for daily staff scheduling.(2)The Supervisor performs subordinate staff shift assignment;the Supervisor can browse employee and shift information but cannot create or delete employee archives.(3)Ordinary store employees can only view their own personal shift schedule,without any modification privilege.
System execution flow starts with user Login.After authentication the system enters the System Home Page,then renders different menu sets and function modules according to the user identity.The Search-employee operation is a reused basic function included(<<include>>)within multiple detail-view use cases.
Inventory management is a conditional could-have requirement reserved for future extension.Advanced features such as attendance registration,department management and a full employee self-service web portal belong to later product iterations and will not be delivered in this release.
